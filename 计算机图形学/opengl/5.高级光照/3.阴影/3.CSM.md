# CSM

本文为 LearnOpenGL 客座文章 [CSM](https://learnopengl.com/Guest-Articles/2021/CSM)（Cascaded Shadow Mapping，级联阴影映射）的中文翻译。

阴影映射（Shadow Mapping）正如 LearnOpenGL 的[阴影映射](https://learnopengl-cn.github.io/05%20Advanced%20Lighting/03%20Shadows/01%20Shadow%20Mapping/)教程所述，是一项强大且相对简单的技术。然而，如果完全按照那篇教程中的方法来实现，勤于钻研的 OpenGL 学习者很快就会发现它的几个不足之处：

- 阴影贴图总是在原点附近生成，而不是在摄像机实际观察的区域生成。当然，如果能为整个场景生成一张分辨率充足的阴影贴图就再好不过了，但在当前的硬件上这是不可行的。实际上，我们希望只为视野内的物体生成阴影贴图，把宝贵的 GPU 显存用在真正重要的地方。
- 阴影贴图的正交投影矩阵没有恰当地贴合到视锥体上。为了让阴影贴图获得尽可能高的分辨率，正交矩阵需要尽可能紧密地贴合摄像机的视锥体，原因同上：如果它更大，就意味着实际可见的物体得到的细节更少。
- 如果我们希望阴影的渲染距离很远（就像第一人称摄像机游戏那样），那么阴影贴图（即使使用了高级的 PCF 函数）也会变得模糊。我们可以通过提高阴影贴图的分辨率来缓解这个问题，但 GPU 显存是我们应当节约使用的资源。

级联阴影映射直接回应了第三点，不过在实现它的过程中，我们也会顺带解决前两点。级联阴影映射的核心洞见在于：对于离我们很远的物体，我们并不需要同等程度的阴影细节。我们希望近平面附近的物体拥有锐利的阴影，而对于几百个单位之外的物体，阴影模糊一些完全没关系：因为根本看不出来。我们要如何做到这一点呢？答案简单得令人赏心悦目：只需为近处的物体和远处的物体分别渲染不同的阴影贴图，然后在片段着色器中根据片段的深度值从相应的阴影贴图中采样。整体算法如下：

- 将我们普通的视锥体分割成 n 个子视锥体，其中第 `i` 个子视锥体的远平面是第 `(i+1)` 个子视锥体的近平面
- 为每个子视锥体计算紧密贴合的正交矩阵
- 为每个子视锥体渲染一张阴影贴图，就好像从我们的平行光视角观察场景一样
- 将所有的阴影贴图发送给我们的片段着色器
- 渲染场景，并根据片段的深度值从正确的阴影贴图中采样

听起来很简单对吧？确实如此，但正如我们的老朋友 OpenGL 经常出现的情况一样：魔鬼藏在细节里。

## 视锥体的世界坐标

在动手处理阴影之前，我们需要先解决一个更抽象的问题：让我们的投影矩阵恰好贴合一个一般的视锥体。要做到这一点，我们需要知道所讨论视锥体的世界空间坐标。虽然乍一听可能令人望而生畏，但我们的工具箱里其实已经备齐了所有必需的工具。回想一下那篇出色的[坐标系统](https://learnopengl-cn.github.io/01%20Getting%20started/08%20Coordinate%20Systems/)教程：视锥体这个被削去顶部的金字塔只会在世界坐标中呈现为那种形状，是我们的观察矩阵和投影矩阵把这个不同寻常的形状变换成了 NDC 立方体。而我们知道 NDC 立方体各个角的坐标：三个轴上的坐标都在 `[-1,1]` 范围内。因为矩阵乘法是一个可逆的过程，所以我们可以对 NDC 立方体的角点应用观察矩阵和投影矩阵的逆矩阵，从而得到视锥体各角的世界空间坐标。

$$
v_{NDC} = M_{proj} M_{view} v_{world}
$$
$$
v_{world} = (M_{proj} M_{view})^{-1} v_{NDC}
$$

```c++
std::vector<glm::vec4> getFrustumCornersWorldSpace(const glm::mat4& proj, const glm::mat4& view)
{
    const auto inv = glm::inverse(proj * view);
    
    std::vector<glm::vec4> frustumCorners;
    for (unsigned int x = 0; x < 2; ++x)
    {
        for (unsigned int y = 0; y < 2; ++y)
        {
            for (unsigned int z = 0; z < 2; ++z)
            {
                const glm::vec4 pt = 
                    inv * glm::vec4(
                        2.0f * x - 1.0f,
                        2.0f * y - 1.0f,
                        2.0f * z - 1.0f,
                        1.0f);
                frustumCorners.push_back(pt / pt.w);
            }
        }
    }
    
    return frustumCorners;
}
```

这里描述的投影矩阵是一个透视矩阵，它使用摄像机的宽高比和 fov，以及当前正在分析的视锥体的近平面和远平面。观察矩阵则是我们摄像机的观察矩阵。

```c++
const auto proj = glm::perspective(
    glm::radians(camera.Zoom),
    (float)SCR_WIDTH / (float)SCR_HEIGHT,
    nearPlane,
    farPlane
);
```

## 光源的观察-投影矩阵

这个矩阵——和普通阴影映射中的一样——是观察矩阵与投影矩阵的乘积，它把场景变换得就像从光源视角看到的那样。计算观察矩阵很简单：我们知道光从哪个方向照过来，也知道它在世界空间中一定看向的那个点：视锥体的中心。视锥体中心的位置可以通过对视锥体各角点的坐标求平均来得到。（这是因为对近平面和远平面的坐标求平均可以得到这两个矩形的中心，而取这两个点的中点就得到了视锥体的中心。）

```c++
glm::vec3 center = glm::vec3(0, 0, 0);
for (const auto& v : corners)
{
    center += glm::vec3(v);
}
center /= corners.size();
    
const auto lightView = glm::lookAt(
    center + lightDir,
    center,
    glm::vec3(0.0f, 1.0f, 0.0f)
);
```

投影矩阵要稍微复杂一些。因为这里的光源是平行光，所以这个矩阵显然必须是一个正交投影矩阵。要理解我们是如何确定矩阵的 left、right、top 等参数的，请想象一下你正从光源的视角观察正在绘制的场景。从这个视角看去，我们要渲染的阴影贴图将是一个轴对齐的矩形，而这个矩形——正如我们之前所确立的——需要紧密贴合视锥体。所以我们需要获取视锥体在这个空间中的坐标，并沿各个坐标轴取坐标的最大值和最小值。虽然乍一听可能令人望而生畏，但这个视角恰恰就是我们的光源观察矩阵变换所给出的。我们需要把视锥体的角点变换到光源观察空间，并找出最大和最小坐标。

```c++
float minX = std::numeric_limits<float>::max();
float maxX = std::numeric_limits<float>::lowest();
float minY = std::numeric_limits<float>::max();
float maxY = std::numeric_limits<float>::lowest();
float minZ = std::numeric_limits<float>::max();
float maxZ = std::numeric_limits<float>::lowest();
for (const auto& v : corners)
{
    const auto trf = lightView * v;
    minX = std::min(minX, trf.x);
    maxX = std::max(maxX, trf.x);
    minY = std::min(minY, trf.y);
    maxY = std::max(maxY, trf.y);
    minZ = std::min(minZ, trf.z);
    maxZ = std::max(maxZ, trf.z);
}
```

我们将用两个矩阵的乘积来创建投影矩阵。首先，我们创建一个正交投影矩阵，left、right、top、bottom 参数设为 `-1` 或 `1`，z 值设为 `minZ` 和 `maxZ`。这会创建一个坐落在原点上的三维矩形，宽和高为 `2`，深度为 (`maxZ` – `minZ`)。在创建实际的投影矩阵之前，我们要先扩大光源视锥体近平面和远平面所覆盖的空间：把近平面“向后拉”，把远平面“向前推”。在代码中，我们通过除以或乘以 `zMult` 来实现这一点。这是因为我们希望把摄像机空间中位于视锥体后方或前方的几何体也包括进来。想一想：能在视锥体内部的表面上投射阴影的，可不仅仅是视锥体内部的几何体！

```c++
// 根据场景调整这个参数
constexpr float zMult = 10.0f;
if (minZ < 0)
{
    minZ *= zMult;
}
else
{
    minZ /= zMult;
}
if (maxZ < 0)
{
    maxZ /= zMult;
}
else
{
    maxZ *= zMult;
}
   
const glm::mat4 lightProjection = glm::ortho(minX, maxX, minY, maxY, minZ, maxZ);

return lightProjection * lightView;
```

把观察矩阵和投影矩阵相乘，我们就得到了给定视锥体对应的光源观察-投影矩阵。我们需要对级联中的每一个视锥体都执行这个过程。

## 2D 数组纹理

在我们消化视锥体贴合的知识的同时，也应该想想如何存储我们的阴影贴图。原则上我们可以做任意多个级联，所以硬编码一个任意的数值似乎不是什么明智之举。此外，为着色器逐个声明并绑定 sampler2D 很快就会让人厌烦。OpenGL 对这个问题有一个很好的解决方案：2D 数组纹理（2D array texture）。这个对象是一个纹理数组，其中的所有纹理都具有相同的尺寸。要在着色器中使用它们，可以像这样声明：

```glsl
uniform sampler2DArray shadowMap;
```

要对它们采样，我们可以使用常规的 texture 函数，纹理坐标参数使用 vec3，第三维指定从哪一层采样，从 `0` 开始。

```glsl
texture(depthMap, vec3(TexCoords, currentLayer))
```

创建数组纹理与创建普通的 texture2D 略有不同。我们使用 glTexImage3D 而不是 glTexImage2D 来分配内存，并且在把纹理绑定到帧缓冲时，使用 glFramebufferTexture 而不是 glFramebufferTexture2D。如果我们了解旧版本，这些函数的参数多少是不言自明的。在调用这些 OpenGL 函数时，我们需要传入 GL_TEXTURE_2D_ARRAY 而不是 GL_TEXTURE_2D 作为 target，以告诉 OpenGL 我们正在处理的是哪种纹理。

```c++
glGenFramebuffers(1, &lightFBO);
    
glGenTextures(1, &lightDepthMaps);
glBindTexture(GL_TEXTURE_2D_ARRAY, lightDepthMaps);
glTexImage3D(
    GL_TEXTURE_2D_ARRAY,
    0,
    GL_DEPTH_COMPONENT32F,
    depthMapResolution,
    depthMapResolution,
    int(shadowCascadeLevels.size()) + 1,
    0,
    GL_DEPTH_COMPONENT,
    GL_FLOAT,
    nullptr);
    
glTexParameteri(GL_TEXTURE_2D_ARRAY, GL_TEXTURE_MIN_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_2D_ARRAY, GL_TEXTURE_MAG_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_2D_ARRAY, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_BORDER);
glTexParameteri(GL_TEXTURE_2D_ARRAY, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_BORDER);
    
constexpr float bordercolor[] = { 1.0f, 1.0f, 1.0f, 1.0f };
glTexParameterfv(GL_TEXTURE_2D_ARRAY, GL_TEXTURE_BORDER_COLOR, bordercolor);
    
glBindFramebuffer(GL_FRAMEBUFFER, lightFBO);
glFramebufferTexture(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, lightDepthMaps, 0);
glDrawBuffer(GL_NONE);
glReadBuffer(GL_NONE);
    
int status = glCheckFramebufferStatus(GL_FRAMEBUFFER);
if (status != GL_FRAMEBUFFER_COMPLETE)
{
    std::cout << "ERROR::FRAMEBUFFER:: Framebuffer is not complete!";
    throw 0;
}
    
glBindFramebuffer(GL_FRAMEBUFFER, 0);
```

把这个纹理绑定到采样器时要小心。再次强调：target 参数需要使用 GL_TEXTURE_2D_ARRAY。

```c++
glActiveTexture(GL_TEXTURE1);
glBindTexture(GL_TEXTURE_2D_ARRAY, lightDepthMaps);
```

到目前为止一切顺利，现在我们已经了解了使用纹理数组的语义。一切看起来都很直接，但 OpenGL 还要给我们出最后一个难题：我们不能用普通的方式向这个纹理中渲染，而是需要做一种叫做分层渲染（layered rendering）的操作。这个过程与我们在[立方体贴图和点光源](https://learnopengl-cn.github.io/05%20Advanced%20Lighting/03%20Shadows/02%20Point%20Shadows/)中所做的非常相似：我们哄骗[几何着色器](https://learnopengl-cn.github.io/04%20Advanced%20OpenGL/09%20Geometry%20Shader/)同时为我们生成多个几何体层。回想一下我们的深度贴图着色器非常简单：在顶点阶段把顶点变换到光源空间，然后用一个空的片段着色器让硬件完成剩下的工作。而在新的深度贴图着色器中，我们只在顶点着色器里进行世界空间变换。

```glsl
#version 460 core
layout (location = 0) in vec3 aPos;
    
uniform mat4 model;
    
void main()
{
    gl_Position = model * vec4(aPos, 1.0);
}
```

新加入的几何着色器看起来像这样：

```glsl
#version 460 core
    
layout(triangles, invocations = 5) in;
layout(triangle_strip, max_vertices = 3) out;
    
layout (std140, binding = 0) uniform LightSpaceMatrices
{
    mat4 lightSpaceMatrices[16];
};
    
void main()
{          
    for (int i = 0; i < 3; ++i)
    {
        gl_Position = 
            lightSpaceMatrices[gl_InvocationID] * gl_in[i].gl_Position;
        gl_Layer = gl_InvocationID;
        EmitVertex();
    }
    EndPrimitive();
}  
```

输入声明中有一个新成员，用于指定调用次数（invocation count）。这个数字意味着该着色器会被实例化，这些实例并行运行，我们可以通过内置变量 gl_InvocationID 来引用当前实例。我们将在着色器代码中使用这个数字来引用我们要渲染到的数组纹理层，以及用哪个阴影矩阵来进行光源空间变换。我们遍历所有三角形，并相应地设置 gl_Layer 和 gl_Position。

（译注：gl_Layer 指定了图元将被写入数组纹理的哪一层，只有渲染到数组纹理或立方体贴图时才会生效。这里的 `invocations = 5` 对应 4 个级联分割平面外加最后一个覆盖到无穷远的层，与上面 glTexImage3D 中 `int(shadowCascadeLevels.size()) + 1` 计算出的层数保持一致。）

> 我强烈建议修改你引擎中的 Shader 类，让它能够在着色器编译之前向着色器代码中插入变量，这样你就可以让 invocations 参数变成动态的。这样一来，当你在 C++ 代码中修改级联的数量时，就不必再修改着色器本身，为你引擎这台复杂的机器卸下一个齿轮。为了简单起见，本教程中没有包含这一点。

片段着色器保持原样，是一个空的直通着色器。

```glsl
#version 460 core
    
void main()
{             
}
```

我们调用该着色器的绘制调用看起来像这样：


## 场景渲染

现在剩下的唯一一件事就是进行真正的阴影渲染。在我们普通的 Phong/延迟渲染片段着色器中，在计算当前片段是否被遮挡的地方，我们需要插入一些逻辑来决定使用哪个光源空间矩阵，以及从哪个纹理采样。

```glsl
// 选择级联层
vec4 fragPosViewSpace = view * vec4(fragPosWorldSpace, 1.0);
float depthValue = abs(fragPosViewSpace.z);
    
int layer = -1;
for (int i = 0; i < cascadeCount; ++i)
{
    if (depthValue < cascadePlaneDistances[i])
    {
        layer = i;
        break;
    }
}
if (layer == -1)
{
    layer = cascadeCount;
}
    
vec4 fragPosLightSpace = lightSpaceMatrices[layer] * vec4(fragPosWorldSpace, 1.0);
```

如果你还记得的话，为了防止阴影痤疮，我们会对图像应用一个深度偏移。这里我们也需要做同样的事情，但要记住：我们现在处理的是多张阴影贴图，每张贴图上的像素所覆盖的空间大小差异很大，像素值增加一个单位，在所有贴图中意味着不同的深度增量。因此，我们需要根据从哪张阴影贴图采样来应用不同的偏移。以我的经验，让偏移与远平面成反比地缩放效果不错。

```glsl
// 执行透视除法
vec3 projCoords = fragPosLightSpace.xyz / fragPosLightSpace.w;
// 变换到 [0,1] 范围
projCoords = projCoords * 0.5 + 0.5;
    
// 从光源视角获取当前片段的深度
float currentDepth = projCoords.z;
if (currentDepth  > 1.0)
{
    return 0.0;
}
// 计算偏移（基于深度贴图分辨率和斜率）
vec3 normal = normalize(fs_in.Normal);
float bias = max(0.05 * (1.0 - dot(normal, lightDir)), 0.005);
if (layer == cascadeCount)
{
    bias *= 1 / (farPlane * 0.5f);
}
else
{
    bias *= 1 / (cascadePlaneDistances[layer] * 0.5f);
}
```

> 请注意，处理阴影贴图时应用偏移有多种不同的策略。我会在引用部分链接几个详细介绍这些策略的资料。

（译注：关于深度偏移和阴影痤疮更详细的讨论，可以参阅本站[阴影映射](https://learnopengl-cn.github.io/05%20Advanced%20Lighting/03%20Shadows/01%20Shadow%20Mapping/)一章中的“阴影偏移”一节。）

函数的其余部分和之前一样，唯一的区别是我们要从 2D 数组纹理中采样，因此需要给 texture 和 textureSize 函数加上第三个参数。

```glsl
// PCF
float shadow = 0.0;
vec2 texelSize = 1.0 / vec2(textureSize(shadowMap, 0));
for(int x = -1; x <= 1; ++x)
{
    for(int y = -1; y <= 1; ++y)
    {
        float pcfDepth = texture(
                    shadowMap,
                    vec3(projCoords.xy + vec2(x, y) * texelSize,
                    layer)
                    ).r; 
        shadow += (currentDepth - bias) > pcfDepth ? 1.0 : 0.0;        
    }    
}
shadow /= 9.0;
    
// 当位于光源视锥体远平面区域之外时，让阴影保持为 0.0
if(projCoords.z > 1.0)
{
    shadow = 0.0;
}
    	
return shadow;
```

就是这样！如果一切都做对了，我们应该能看到渲染器会根据距离在阴影贴图之间切换。试着设置一些不合理的级联分割平面距离（例如只设置一个，离摄像机几个单位远），看看代码是否真的在起作用。你应该能看到分割平面两侧的阴影质量有明显下降。如果屏幕上出现了摩尔纹伪影，试着调整一下偏移参数。

## 结语

在提供的示例项目中，你可以按 F 键切换深度贴图的可视化。处于深度贴图可视化模式时，你可以按 + 键在不同的层之间切换。

浏览代码时你可能会好奇为什么 UBO 数组的长度是 `16`。这只是一个随意的选择，在我看来不太会有人使用超过 `16` 个阴影级联，所以 `16` 看起来是个不错的分配数字。

在代码示例中，立方体的位置和旋转是随机的。如果你想用静态几何体来尝试这个示例，我建议你为[随机数生成器](https://en.cppreference.com/w/cpp/numeric/random/mersenne_twister_engine)设置种子。

如果你阅读下面给出的资料，可能会注意到 NVIDIA 的文章在构建光源投影矩阵时采取的方式相比本文要绕一些。不过，就光源观察空间中的 x-y 坐标而言（这才是关键所在），他们所做的与我们所做的是数学等价的。把数值代入 songho 的[这篇文章](http://www.songho.ca/opengl/gl_projectionmatrix.html)给出的矩阵中，就能看出这一点。
